把一场招聘会的 308 家企业、1406 个岗位做分类，第一版跑出来是这样：

| 类别 | 数量 |
|---|---:|
| **其他 / 未注明** | **303** |
| 职能 / 管培 | 169 |
| 工艺 / 制造 | 162 |

**21.5% 的岗位没归进去。** 当时我跟自己解释：这些岗位名太模糊了，「研发工程师」不写方向，我怎么知道归哪。

这是偷懒。翻回去看那 303 条，答案其实都写在旁边的单元格里——**公司是做什么的**。

## 问题出在只用了一个维度

原逻辑很直接：遍历关键词表，命中就归类，没命中就扔「其他」。

```python
for c, pri, kws in CATS:
    if any(k in name for k in kws):
        return c, pri
return '其他', 0
```

但招聘会的岗位名有大量**通用职称**：

- 研发工程师（25 条）
- 产品工程师、系统工程师、助理工程师
- 技术员、技术储干、专业技术岗

这些词本身不含方向信息。**方向在第二个维度里：这家公司做什么。**

「研发工程师」出现在：
- 胜科纳米（半导体）→ 应该是芯片 / 半导体
- 贝特利高分子（材料）→ 应该是材料 / 化工
- 泰伦机械（装备）→ 应该是机械 / 结构
- 孚新汽车（汽车电子）→ 应该是汽车类

同一个岗位名，四种正确答案。

## 改成两级判定

第一级照旧走岗位名关键词，第二级用**企业行业**兜底：

```python
def cat_of(name, industry=None):
    t = name.lower().replace(' ', '')

    # ① 教师 / 科目名优先
    if any(k in t for k in EDU_WORDS):       return '教育 / 科研', 0
    if any(t.startswith(s) for s in SUBJECTS): return '教育 / 科研', 0

    # ② 名称关键词：先括号前主干，再全名
    head = re.split(r'[（(]', name)[0].lower()
    for c, pri, kws in CATS:
        if any(k in head for k in kws): return c, pri
    for c, pri, kws in CATS:
        if any(k in t for k in kws):    return c, pri

    # ③ 笼统职称 → 按企业行业兜底
    if industry:
        target = IND2CAT.get(industry)
        if target and target != OTHER:
            return target, PRI[target]

    return OTHER, 0
```

`IND2CAT` 就是一张行业到类别的映射表：

| 企业行业 | 默认类别 |
|---|---|
| 半导体/集成电路 | 芯片 / 半导体 |
| 材料/化工 | 材料 / 化工 |
| 汽车/轨交/航空 | 汽车 / 轨交 / 航空 |
| 高端装备/机器人 | 机械 / 结构 / 设计 |
| 生物医药/医疗器械 | 生物医药 / 医疗 |
| 软件/互联网/AI | 软件研发 |

结果：**303 → 0**。

## 顺带修掉的三个行业判定 bug

行业判定原来也是关键词匹配，一样会错。三个真实的例子：

| 企业 | 判成了 | 为什么错 | 正确 |
|---|---|---|---|
| 大飞机江苏太仓研究中心 | 医院/科研院所 | 名字含「研究中心」，简介里又有「上海飞机设计研究院」 | 汽车/轨交/航空 |
| 中国科学院苏州纳米所 | 教育/学校 | 「中国科学院」里含「学院」，和「研究所」打平后按顺序输了 | 医院/科研院所 |
| 贝特利高分子材料 | 电子信息/通信 | 简介里的「电子」压过了名字里的「材料」 | 材料/化工 |

修法是两条：**名称强特征优先判定**，以及**名称命中权重必须压倒简介命中**。

```python
def ind_of(name, intro):
    # ① 名称强特征，命中即返回
    if any(k in name for k in ['飞机','航空','航天','船舶','轨交','轨道交通','汽车']):
        return '汽车/轨交/航空'
    if any(k in name for k in ['研究所','研究院','研究中心','科学院']) and '职业技术' not in name:
        return '医院/科研院所'
    if any(k in name for k in ['学校','中学','大学','学院','职业技术']):
        return '教育/学校'

    # ② 加权：名称命中数优先，其次才是总分
    best, best_key = '其他/综合', (0, 0)
    for nm, kws in IND:
        nh = sum(1 for k in kws if k in name)      # 名称命中
        ih = sum(1 for k in kws if k in intro[:120])  # 简介命中
        if (nh, nh*3 + ih) > best_key:
            best, best_key = nm, (nh, nh*3 + ih)
    return best
```

`(nh, nh*3+ih)` 这个元组比较是关键——先比名称命中数，再比总分。这样「简介里出现一次研究院」永远打不过「名字里就写着半导体」。

## 还有两条容易忽略的规则

### 教师比 AI 优先

「人工智能学院专任教师」含「人工智能」，会被 AI 抢走。但它是教师岗。

所以教育类要**前置判定**，不能放在类别列表里靠顺序：

```python
if any(k in t for k in ['教师','讲师','研究员','博士后','科研','教研']):
    return '教育 / 科研', 0
```

同理，「语文 / 数学 / 英语 / 物理」这种只有科目名、没写「教师」的岗位，也是教育。

### 先匹配括号前的主干

- 「机械工程师（视觉方向）」——括号里有「视觉」，但它是机械岗
- 「算法工程师（视觉）」——主干就是算法，归 AI

```python
head = re.split(r'[（(]', name)[0]
```

先拿 `head` 去匹配，匹配不上再用全名。两条都对。

## 别给「助理」这种万能后缀建规则

第一版给职能类加了 `助理` 和 `专员`，结果：

- 研发助理 → 职能 ❌
- 产品助理 → 职能 ❌
- 项目助理 → 职能 ❌

它们应该是研发 / 产品 / 项目岗。**「助理」是后缀不是方向**，只能保留「总经理助理」「人事助理」这种组合词。

## 结果

| | 第一版 | 现在 |
|---|---:|---:|
| 其他 / 未注明 | 303（21.5%） | **0** |
| 岗位类别数 | 17 | 20 |
| 重点岗位（软件/AI/嵌入式/机器人） | 158 | 170 |

20 类里新增的三个，都是为制造业招聘会补的：

- **汽车 / 轨交 / 航空**（31 条）：机务、总装、标定、线束、底盘
- **材料 / 化工**（39 条）：配方、合成、表征、电镀、热处理
- **生物医药 / 医疗**（32 条）：临床、注册、试剂、发酵、纯化

## 一条可以带走的检验标准

如果你也在做类似的数据清洗，给自己定一条硬指标：

> **「其他 / 未注明」超过 5%，就是分类器有问题，不许交付。**

我把它写进了 Skill 的强制检查项。因为一旦允许自己「剩下的先扔其他」，就会一路扔到底。
