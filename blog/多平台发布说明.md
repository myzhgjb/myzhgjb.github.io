## 各平台的能力边界（重要）

| 平台 | 有官方发布接口吗 | 本脚本能不能发 | 说明 |
|---|---|---|---|
| **博客园** | ✅ MetaWeblog | ✅ 能 | 需要「访问令牌」，稳定 |
| **微信公众号** | ✅ 草稿箱接口 | ✅ 能（到草稿箱，群发仍需手动点） | 需要 AppID/AppSecret + 服务器 IP 白名单 |
| **掘金** | ❌ 无官方 | ⚠️ 只能 cookie 调内部接口，随时失效 | 建议手动粘贴 |
| **CSDN** | ❌ 无官方 | ⚠️ 同上 | 建议手动粘贴 |
| **知乎** | ❌ 无 | ❌ 明确禁止自动化 | 只能手动 |

> 公众号草稿接口还有个硬限制：**个人订阅号无法通过接口群发**，只能建草稿，需要你在后台点「群发」。这是微信的规则，不是脚本的问题。

## 用法

```bash
cp publish.config.example.json publish.config.json   # 填凭据，别提交到 git
python publish.py --check                            # 看文章和凭据状态
python publish.py --platform cnblogs --dry-run       # 先空跑
python publish.py --platform cnblogs                 # 真发
python publish.py --platform wechat                  # 发到公众号草稿箱
```

## 手动发布的建议顺序

1. **掘金**先发（技术社区，收录快，对 SEO 友好）
2. **CSDN** 次之（流量大，长尾搜索强）
3. **博客园** 用接口发（最省事）
4. **知乎** 发「文章」而不是「回答」，标题改成问句形式更容易被推荐
5. **公众号** 最后发（排版要重新调，建议用 mdnice 转一下样式）

## 平台适配（同一篇内容，标题和开头要改）

| 平台 | 标题风格 | 开头 | 排版 |
|---|---|---|---|
| 掘金 | 保留原技术标题 | 直接上结论 + 配图 | 支持 Markdown |
| CSDN | 可在标题加「（附源码）」 | 先列目录 | 支持 Markdown |
| 博客园 | 原标题 | 可加一句「本文记录…」 | 支持 Markdown |
| 知乎 | 改成问句，如「如何评价…」「怎么把…」 | 先给结论，再展开 | 支持 Markdown |
| 公众号 | 短、有钩子，如「我把 308 家企业的招聘会做成了…」 | 前 3 行必须留住人 | 需转 HTML，图片要重新上传 |
